# Deterministic disassembly planner

The planner discovers complete target-removal routes using the existing OCCT
geometry engine. A feasible route has passed independent forward replay. The
separate `replacement_verified` field also requires reverse restoration and all
mandatory constraints. Neither field certifies a physical repair or a product.

## Run

The existing virtual environment is ready on this machine. From the repository
root:

```sh
backend/.venv/bin/unlock-engine plan-demo --output backend/.work/planning
backend/.venv/bin/unlock-engine plan \
  --step backend/.work/planning/inputs/sequence/assembly.step \
  --manifest backend/.work/planning/inputs/sequence/manifest.json \
  --target target --output backend/.work/my-plan
backend/.venv/bin/python -m pytest backend/tests -q
```

The demo generates genuine synthetic STEP assemblies and runs separate native
workers for B01, B02, B03, a B03 cover selection, a screw-and-cover sequence, and
T01/T02 revisions. All action sequences come from search. `result.json` contains
steps, authoritative placements, certificates, rejected actions, metrics, replay,
reverse checks and limits. `latest.json` points to the actual content-addressed
artifact. Starting a CLI run archives prior evidence and marks the output running.
Cancelled, incomplete and invalid runs replace that marker with their own result;
they cannot leave an earlier passing result as the current analysis.

Exit codes: 0 for completed feasible or scoped no-path analysis, 2 for an
incomplete, cancelled or invalid planning problem, 1 for a CLI/configuration error.
`--max-states` and `--max-seconds` may lower the default limits of 4096 and 30s.
`--expected-revision-id` rejects stale coordinator requests.

## Public integration surface

```python
from unlock_engine.package import load_files
from unlock_engine.planning.runner import isolated_plan, save_result
from unlock_engine.planning import SearchPolicy

package = load_files({"assembly.step": step_bytes, "manifest.json": manifest_bytes})
result = isolated_plan(package, "target", SearchPolicy(), cancel_event=event)
artifact_id = save_result(result, output_directory)
```

`isolated_plan` is the coordinator entry point for native work. It accepts a
validated local package and optional server-validated template request with only
`bracket_id`, `template_id`, and `parameters`. It constructs and independently
checks that candidate before searching. It accepts no caller success flags,
generated Python, alternate collision checker or model-authored action list.

For controlled engineering scripts/tests, `Problem(revision, target, policy,
candidate=...)`, `plan_revision`, and `plan_problem` run in the caller's process.
Use them inside a bounded native worker, not an HTTP handler. `replay_plan` and
`validate_reverse` expose independent validation. `compare_revisions` recomputes
both sides; `compare_plans` accepts trusted service-produced/persisted results and
checks their content identity, metrics, revision lineage and compatibility.
Do not expose arbitrary client JSON as authoritative comparison evidence.

`retrieve_result(directory, artifact_id)` verifies the artifact hash and result
identity and labels the response `provenance="retrieved"`. This does not claim a
new analysis. Schemas are generated by `unlock-engine schemas --output ...`:
`PlanResult`, `Step`, `Action`, `Certificate`, `Rejection`, `Metrics`,
`ValidationReport`, `SearchPolicy`, and strict `ErrorEnvelope`, alongside the existing CAD contracts.

No HTTP server, job database, frontend wiring or Meta inference is added. The
existing STEP export remains available with its existing round-trip checks;
planner JSON can accompany that CAD bundle. Render meshes remain nonauthoritative.

## State and finite graph

`State` is an immutable removed-occurrence frozenset plus last tool ID. Connection
states are derived from that set and the frozen manifest. Remaining occurrences
stay at their STEP placements. Shared definitions and duplicate display names do
not merge instances. The target must be a replaceable nonfastener. Only its
certified translation to its declared exterior stage reaches the goal.

Candidates are enumerated by occurrence ID then axis, as specified by PRD §14.
Each screw has one annotated abstract REMOVE_FASTENER action. One annotation can
retain several components. Installed screws prevent moving their explicitly
retained components and their host (carrying an installed screw is unsupported).
Unannotated screws stay obstacles and have no executable removal action.

For each permitted part axis, the frozen endpoint rule is:

1. Honor mandatory explicit path direction/distance constraints when declared.
2. Otherwise select the nearest endpoint with a 0.02mm interior guard that fits
   the stage and lies beyond the assembly envelope plus required clearance.
3. Reject an axis with no such endpoint. Do not create intermediate part states.

This is a finite supported operation graph, not a search over arbitrary endpoints.
Multiple mandatory axes for one occurrence cannot be fulfilled by one removal
and are rejected as unsupported metadata. Unknown connection types fail the whole
existing readiness gate, even outside the selected target's closure. This is a
disclosed conservative restriction, not a silently ignored connection.

## Geometry and evidence

Semantic checks run first. Legal candidates use `motion.validate_translation`,
`tools.evaluate_fastener` and actual shaft/handle solids. Every remaining solid
and keep-out participates, regardless of frontend visibility. Removed occurrences
are omitted only after a clear certified action. Fastener extraction uses its
explicit annotation distance; taking the released screw away is part of that
abstract operation. Threads, rotation, forces and handling after extraction are
outside the model.

Known-family material decompositions require matching actual imported material or
trusted candidate reconstruction. Motion independently validates their coverage.
Proxy interval separation may certify a full continuous segment; sampled BRep
queries can only reject or return unknown. Positive material intersection,
subthreshold measured gap, numerical uncertainty, tool blockage and semantic
failure retain separate evidence. A proxy overlap never becomes a collision claim.

Cache keys bind actual geometry, revision, full manifest/constraints, policy,
tools/engagements, removed occurrences, last tool, operation, distance and mode.
The representation is part of input identity. Planning context mappings and policy
are sealed; changing a tool or stage requires a new problem. Integrity checks of
the original, current and keep-out BReps precede cache use.
Fresh replay uses an empty transition cache and compares regenerated certificates,
action IDs, prerequisites, state hashes and placements with the saved route.

Reverse validation restores occurrences in exact reverse order. Every inverse
translation runs again through the CAD validator. Named terminal planar contacts
are checked at the assembled endpoint using the inverse separating half-space
proof, with every other material pair still swept. Screws additionally need fresh
tool access, insertion geometry, and restored hosts/retained components. Final
connections must match the initial state. Removal feasibility and replacement
eligibility are separate results.

## Search, limits and claims

UCS uses Python `heapq`, stable serial ties, full-state best costs, stale-entry
checks and parent reconstruction. Its additive lexicographic cost is unrelated
nonfastener removals, fasteners, tool changes, total operations. Initial tool
pickup is free; hand translation preserves last tool. Metrics are recomputed from
saved actions and certificates. Clearance is a certified conservative bound when
available; contact exemptions do not invent a positive gap.

`complete=true` on a feasible result means UCS settled a goal with conclusive
lower-cost alternatives, not that every higher-cost state was explored.
`optimal_within_scope=true` applies only to that finite supported graph. Any
observed unknown transition conservatively withholds optimality and completeness,
even if a route was found. No-path requires exhausted frontier, no unknown edges
and no interruption. A limit without a checked goal is incomplete. A goal known
before a cooperative search limit may be replayed and returned feasible with
optimality unproven. Cancellation discards the uncommitted result.

Search uses a monotonic 30s deadline and a 4096 expanded-state cap. The parent also
enforces the search deadline while native code is running and kills an unresponsive
worker. Separate native import (60s), preparation, replay, reverse and final-check
phases (30s each) have their own limits, with a 180s whole-worker cap. Search time
excludes import and preparation. A hard interruption returns incomplete/cancelled
with the last durable checkpoint and explicit error; an uncommitted route is not
promoted to feasible. Linux has an 8GiB address-space cap; macOS does not. CPU/core/
output-file limits remain enforced. A future coordinator must queue native jobs;
this subsystem is not a multi-user scheduler.

Comparison freezes target, semantics, constraints, tools, stages, numerical/search
policies, objective, revision lineage and template restrictions. A revised result
needs all mandatory checks and reverse restoration. Infeasible-to-feasible has no
baseline percentage. Feasible-to-feasible improvement requires a smaller tuple,
no increased listed count, and proven supported optima. Incomplete comparisons
remain best-found observations without a global improvement claim.

## Tests and boundaries

The independent reference solver enumerates all legal sequences without a heap,
production cost updater, state transition or UCS memoization. It checks tiny exact
graphs, including a longer preferred route and tool grouping. A second reference
enumerator uses actual CAD eligibility on the screw-and-cover fixture and checks
all four routes (two cover axes times two screw orderings).

Integration tests use genuine STEP/XDE import, actual BReps, thin hidden material,
unknown proxy overlap, named seats, shaft/handle access, candidate T01/T02 geometry,
replay corruption, source immutability and JSON Schema. Fault injection tests
raise a native error or launch a real crashing/unresponsive process; they never
mock geometry success.

Supported boundaries remain the existing CAD engine's 5–12 rigid single-solid
occurrences, explicit millimetres, six world axes, known contacts, annotated
reusable screws, finite templates and 500mm envelope. No temporary movements,
subassembly carrying, arbitrary rotation, force, torque, friction, flex, cables,
strength, electrical safety, manufacturing or restored-function assessment.
These synthetic models have simplified screw mating and assumed workholding.
Real-product qualification and independent mechanical review remain outstanding.
Linux/container validation and fixture redistribution licensing remain open from
the earlier phase. See PLANNER_HANDOFF.md for executed evidence and measurements.
