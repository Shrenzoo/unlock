UNLOCK Prioritized Implementation Backlog
Development handoff aligned with PRD version 1.0
Each item has an intended owner, dependency, acceptance criterion and verification method. A owns frontend, workflow and integration. B owns geometry, search and model integration. Both review correctness and evidence. All effort estimates are provisional focused developer hours, not elapsed commitments. Parallel work requires frozen contracts; unresolved geometry takes precedence over presentation.
Delivery order and capacity
Start with E0 and E1, then run E2 and frontend E5 against fixed schemas. Build E3 and E4 before polishing comparison. E6 evaluation begins with the first geometry primitive and becomes a final release gate; E7 closes deployment and submission. P0 items total approximately 108 to 159 focused hours across the two developers, before contingency; availability has not been confirmed. Reserve about 20 percent additional time. If capacity is smaller, cut P1 and P2 first, then narrow fixture coverage while keeping a complete verified loop.
All requirements and error semantics are defined in the full PRD. An item is complete only when its acceptance evidence is linked to the appropriate revision or test artifact. Work that produces only a UI mock or hardcoded result does not close an engineering item.
